## 关键经验
- 源 OCR 损坏识别：若某章 `第X章` 在正文出现次数=0(或仅交叉引用如"在第二章中")，则源缺失该章标记，务实做法=整洁前置页+完整 TOC 列表+正文幸存章首规范，绝不强行重排(易错位)。
- 粘连章首必须前置 `\n\n` 才能成独立标题行(原粘连在前文非行首，光加`#`不生效)。
- `cut -c1-N` 在管道里会截断多字节 UTF-8 显示出"乱码"，但文件本身是合法 UTF-8——别被误导(原子/中国古建筑文化之旅最初误判为乱码，实为管道显示问题)。
- 修复脚本跑乱工作区时：`git checkout HEAD -- <file>` 恢复原始 OCR 再干净重跑。
- 临时 `_fix_*.py` 留在仓库根会被 WPS 云同步复活，跑完即 `rm -f`；git 状态里 `??` 残留目录(2-曼昆/7/7e/david-tong/stat-mech/温州乡土建筑chap1-2)不提交。
- WPS 云同步会偶发把工作区文件改乱(本轮回发现 原子130k 正本被临时截断 429 行，已 `git checkout HEAD` 恢复，提交时确认为有效 130k 正本)。
- 提交用 `git add -u`(只暂存已跟踪修改，天然排除 `??` 临时脚本/失效目录)；中文路径勿用 `git add $(git diff --name-only)`(引号导致 pathspec 失败)。
